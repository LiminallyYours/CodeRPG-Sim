# PLAN: phase 1 of the simulation fork

Written 2026-10-24 by Claude with JW, from `SIMULATION-FORK-PROPOSAL.md` (the design) and JW's answers in the first fork session. Status: **approved by JW, 2026-10-24**, with assumptions A, B and C confirmed. **Phase 1 closed, 2026-10-24** (fourth session).

Each numbered step is one commit. Every step runs `sh tools/check.sh` before and after. A step marked **dry run** changes what players are told, so before it is committed it also gets a seeded dry run in a scratch copy (`cp -R . /tmp/sim-test`), with the `brief` entries read for anything outside the fiction. Nothing is pushed until JW asks; `origin` must point at `LiminallyYours/CodeRPG-Sim` first (JW runs `git remote set-url`).

## Decisions taken in the first session (JW, 2026-10-24)

These settle the proposal's section 12 and the housekeeping. Step 1 writes them into the proposal.
1. **Memory:** 5 rounds kept word for word; condense every 5 rounds, so a character sees 5 to 10 rounds in full; plus a size cap that condenses early. All of it in the settings file, not code.
2. **Settings file:** every tunable of the simulation lives in the existing settings mechanism (`rules/presets.json` + each game's `settings.json`, changed with `tools/settings.py`), in a new `simulation` preset. Rule numbers and prices stay in `balance.json`. Rejected: a new config file, since the existing one already validates keys and has an owner's tool.
3. **Time:** the world's clock moves **once per round**, not per walk. World turns every N rounds, building times in rounds, weather and time of day by rounds. Rejected: counting every character's walks; time would stop when characters stay put and would run faster with a bigger cast, so runs couldn't be compared.
4. **First world:** The Thirteenth Stroke, moved from `state/worlds/` into `games/`. The backend stays world-independent (DEVELOPING.md invariant 7): no code, skill, check or dashboard names a world. **Forging new simulation worlds** (the worldsmith aiming at `--sim-complete`) is **phase 2**.
5. **Dice lines:** characters are **not** shown them by default; the story tells them what happened. A setting (`brief.dice_lines`) turns them on for comparison runs. This is a recorded exception to the proposal's section 2.
6. **Model per character:** the Agent tool takes a `model` at spawn (verified 2026-10-24: `npc` defined as Sonnet ran as Haiku when asked). One `player.md`; the referee passes the cast entry's model. Rejected: one agent file per model.
7. **Repository:** this folder, name CodeRPG-Sim, copied git history kept, new remote `github.com/LiminallyYours/CodeRPG-Sim`.
8. **The original's planning papers** are deleted from the fork (recoverable from git history and the original folder).
9. **Referee:** one turn procedure. `gm-turn` itself is edited to act for a named character and store the story with `narrate`; no second copy. The game-master `CLAUDE.md` and the in-game reminder hook are replaced **early** (step 3), so JW no longer needs `ooc:`.

Verified facts the plan relies on: `tools: []` + `omitClaudeMd: true` still give an agent no file tools and no `CLAUDE.md` (Claude Code's agent list wrongly labels such agents "All tools"); about 100 references to the single player's fields across 37 functions of `rpg.py`; the move counter (`tick_move`) drives the deadline clock, weather, time of day, building completion and world turns.

## Assumptions (confirmed by JW)

- **A. The two shipped games stay** in `games/` next to The Thirteenth Stroke, each with a small two-character `cast.json`, so the engine tests run the simulation on three worlds and prove nothing in the backend is tied to one. Only The Thirteenth Stroke gets the full simulation content and must pass `--sim-complete`. The alternative is deleting them, which leaves one world and no proof of world-independence until phase 2.
- **B. Phase 1 built rooms** record an `owner` and have one use, `stash`. The proposal's phase 2 says "room uses beyond stash", which puts stash in phase 1.
- **C. Contests** (two characters reaching for the same thing in the same turn) wait for phase 2 with trades. In phase 1 the round order decides who gets there first.

### Stage 2: the record
9. **The log.** `state/log/<run id>.jsonl`, written through one function. This step logs `command` (each command run with `--as`, and its output) and `coins` (every change, with a reason). `coins` gains `--reason <job|work|sale|order|reward|...>`, required in simulation saves; `pay` and effects pass their own. `rpg.py log [n]` prints the last entries. Tests: every coin change in the log has a reason; the log is valid JSON lines.
10. **Rounds.** `round start` draws the order: a balanced shuffle from the run's seed and the round number, logged with the draw; `round end` checks every character acted, runs the world's clock tick (moved out of `move`'s `tick_move`: weather, time of day, building completion, world turn due every `world_turns.every_moves` ticks, which are rounds when `rounds.clock` is `round`) and logs the summary. A world turn that falls due runs at the round's end, so no character acts in the middle of one. Tests: the same seed draws the same orders; over 30 rounds no character goes before another more than a set margin more often; `move` no longer ticks the clock in a simulation save; a building finishes after its rounds.
11. **A player's turn, and memory** (built before the orders step, which needs each turn's own words; as built 2026-10-24). `reply <id> <file>` takes the player agent's reply (`DO:` and `JOURNAL:`) from a file in `proposals/` and opens their turn; `narrate <id> <file>` stores the story they're told and ends it. Files, not shell arguments, because the text carries quotes and apostrophes. In an open round only the player whose turn it is can be acted for; `round end` waits until every player's turn is narrated. Memory entries carry round, kind (`seen`, `told`, `did`, `reasoned`) and a times-shown count. `memory condense <id>` prints the condensing brief once the recent layer holds `recent_rounds + condense_every` rounds or passes `max_chars`; `memory store <id> <file>` folds those rounds into the player's own words; the log keeps the originals. Only the `self` condenser is built. Tests: turn order is enforced; condensing stores and trims; a store with nothing waiting, or after the memory changed, is refused.

23. **Personal flags.** A game's `world.md` may list `personal_flags:`, things a person learns or goes through. `flag set|unset <name> --as <id>` keeps a personal flag in that person's own record (`flags`, read with `.get`, so no `STATE_VERSION` bump); every other flag stays shared. `condition_flags` reads the shared flags plus the acting person's own, so quests, `## If` sections and character files follow each person; a world turn (no one acting) sees only the shared ones. `validate` refuses a personal flag that isn't a plain flag name, or one that decides where things are: in a room's exits, characters or items, or a plan's `when` or `sets` (else the world splits: Grukk on the bridge for one person and gone for another). The lists: The Thirteenth Stroke `heard_of_shadows`, `caught_sneaking`; The Dark Lighthouse `lamp_quest_started`, `mirror_cursed`, `tongue_salted`; The Flooded Station `halloran_briefed`, `radio_habit`, `habit_broken`. Curses become per person by this, but `curses.on` stays off in the simulation. Tests: one person's knowledge flag leaves another's quest unstarted; a character file's `## If` section follows the person acting; `validate` refuses a personal flag in an exit, placement or plan.

Refused when no one else was there, when too long (`balance.json` `turns.witnessed_chars`, 800), or out of turn. `say` stays as it is: the actor's own words, exactly. Tests: the note reaches onlookers in both rooms and no one else; refused with no one there and when too long.

## How a trade works
- **An offer is something said and something recorded.** When a DO line offers a trade to someone present ("two buttons for your poker", "take my thimble"), the referee stores the words with `say`, as now, and the terms with `trade offer <file> --as <id>`: a small JSON file naming who it's for, what the offerer gives and what they want back: belongings (things made to order among them) and coins, either side may be empty (a gift asks nothing). `rpg.py` refuses an offer to someone not here, of something the offerer doesn't hold, of coins they don't have, or naming anything but belongings and coins (a built place can't change hands yet). It doesn't check whether the other has what is asked for: that is theirs to know, and the accepting decides.
- **The one it's for decides, on their own turn.** Their next brief shows it in the pane, under `## Offered to you` (Hobb Ashcombe offers you 2 buttons for your Lamplighter's Pole), beside the words they heard. If their DO line takes it, the referee runs `trade accept <tN> --as <id>`; if it turns it down or ignores it, `trade decline <tN>`, or it lapses. A counter-offer is a decline and an offer of their own. Nobody ever accepts for anyone else.
- **Accepting hands things over, all or nothing.** Both must be in the same place, both must still hold their side, and the one taking things must be able to carry them (`check_carry`); then the items change hands (a thing held in hand is let go of first), coins move with reason `trade` for both (the log's `coins` entries), and the log keeps `trade` entries for `offered`, `accepted`, `declined` and `lapsed`, with the terms and both journal lines. A thing made to order that changes hands gets an `order` `used` entry (`traded`), as proposal 8.1 asks. A gift is accepted like any offer, so nobody is handed something they didn't take. The others there see it as usual, through the onlookers' note.
- **Not in this step:** harm, theft and cheating (decided out in section 10); haggling with the world's makers (prices stay fixed); places changing hands; a same-round back-and-forth (6.5's `lines_per_exchange` idea).

## What one-at-a-time turns leave of proposal 6.4
Proposal 6.4 says: when two people want the same thing in the same round, the order decides (the later one finds it gone); when two reach for the same thing in the same turn ("one grabs what another is holding, both claim a job"), `check` decides it: each rolls d20 plus the fitting attribute, higher wins, both rolls logged (a `contest` entry, 8.1). But a turn here belongs to one person, and nobody else acts in it. So "the same thing in the same turn" can only happen when the person whose turn it is acts against someone else who is there: reaching for what the other holds. A thing lying on the ground, a job someone offers, a maker's time: whoever's turn comes first gets it, as now. (Getting past someone who has said they're standing in a doorway would need a person's stance to last until their next turn; not in this draft.)

In JW's two runs nobody tried it. The first was the seventh session's test run, round 6: Hester offered Hobb the poker, walked off with it in the same breath, and Hobb followed her to "take the poker". Today `gm-turn` lets nothing happen and the story says why.

## How a contest would work (proposed)
- **Only an open grab** at something another person plainly holds, on the grabber's turn, with both in the same place. Coins aren't grabbed (they're in a pocket); nor is anything in a stash or a built place. Nobody is hurt: harm stays out.
- **The one grabbed at holds on, and isn't asked:** nobody is asked whether they feel a blow either. They hear what happened (the onlookers' note, which they're among) and answer on their own turn, as themselves: ask for it back, grab it back, let it go.
- **`contest <stat> <their id> <their stat> --take <item> --as <id>`:** refused, with nothing rolled, if they aren't here, it isn't the grabber's turn, they don't hold that item, or the grabber couldn't carry it. Otherwise d20 + the grabber's stat against d20 + theirs; the higher wins and a tie goes to the one holding it. A win moves the item (let go of first if it was in hand), with an `order` `used` entry (`snatched`) for a thing made to order; a loss changes nothing. Logged as a `contest` entry: both stats, both rolls, the winner, the item. It prints `CONTEST: … -> <winner>` for the story, which tells the outcome as fiction, never the numbers.

## Questions for JW
1. **Should one person be able to take something out of another's hands at all?** When the design was agreed (proposal section 10), harm between people (theft, fighting, cheating) was left out, and today the referee never lets a grab succeed. But proposal 6.4 names exactly this, "one grabs what another is holding", as the main contest. Since people act one at a time, a grab is nearly the only thing a contest could settle; everything else is settled by who goes first. Options: **(a)** yes, an open grab only, settled by dice, nobody hurt (recommended); **(b)** no: keep refusing, and drop contests from phase 2; **(c)** yes, and also taking things unseen (picking a pocket), where the holder would learn of it only if they caught the thief.
2. **Does the one grabbed at get a say before the dice?** They can't be asked in the middle of someone else's turn without breaking the one-at-a-time turns. **(a)** They hold on by reflex, the dice decide at once, and they respond on their own turn, knowing what happened (recommended). **(b)** The grab waits, like an offer: they see it on their own turn and choose to hold on (then the dice) or let go. A grab would then take two turns, with the grabber's hand out the whole time.
3. **A tie:** **(a)** the one holding it keeps it (recommended); **(b)** roll again.
4. **Which of their three attributes each side uses:** **(a)** the referee picks the fitting one for each, as for any check, from how they go about it: Gumption (might) to wrench something away or hold on tight, Wiggle (agility) to snatch quickly or whisk it out of reach (recommended); **(b)** always Gumption against Gumption, so the strong always have the edge.
5. **How to see it working, since people have tried it only once:** **(a)** a staged test: a scratch copy played forward until two people are together and one holds something, then one person's reply written by hand ("I grab the poker out of Hester's hands") in place of their model's, with the real referee running the round (about $0.50), and then watching for it in the next ordinary run (recommended); **(b)** only wait for it to come up in ordinary runs.

## The bar for now (JW, twelfth session, 2026-10-26)
The project has four parts: **the people** (how agent-players are built and managed, and meet the worlds they're given), **the worlds**, **the mechanics** (world-agnostic: Claude Code and code making it all move and keep to rules), and **the reporting** (the owner's view in: the dashboard). The goal of this phase is **all four working together**, each with just enough to test the mechanics and to be extended later; refining each comes after. Wendleford and the dashboard are test cases for the mechanics. **Four people is this phase's test target only**: the number of people in a world must stay dynamic (today a world's cast is limited only by the `cast.max_players` setting, 6). Later, outside this project but to be supported by it: a tool that generates people and worlds from templates to meet testing requirements, so the file formats (archetypes, cast entries, world files) and the checks (`validate --sim-strict`) are the interfaces to keep clean. A step is drafted by asking whether it's needed for the parts to work together, or to keep them extensible; anything else goes under *Future discussions*.
