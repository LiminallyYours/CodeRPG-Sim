# PLAN: phase 1 of the simulation fork

Written 2026-10-24 by Claude with JW, from `SIMULATION-FORK-PROPOSAL.md` (the design) and JW's answers in the first fork session. Status: **approved by JW, 2026-10-24**, with assumptions A, B and C confirmed.

Each numbered step is one commit. Every step runs `sh tools/check.sh` before and after. A step marked **dry run** changes what players are told, so before it is committed it also gets a seeded dry run in a scratch copy (`cp -R . /tmp/sim-test`), with the `brief` entries read for anything outside the fiction. Nothing is pushed until JW asks; `origin` must point at `LiminallyYours/CodeRPG-Sim` first (JW runs `git remote set-url`).

## Decisions taken in the first session (JW, 2026-10-24)

These settle the proposal's section 12 and the housekeeping. Step 1 writes them into the proposal.
1. **Memory:** 5 rounds kept word for word; condense every 5 rounds, so a character sees 5 to 10 rounds in full; plus a size cap that condenses early. All of it in the settings file, not code.
2. **Settings file:** every tunable of the simulation lives in the existing settings mechanism (`rules/presets.json` + each game's `settings.json`, changed with `tools/settings.py`), in a new `simulation` preset. Rule numbers and prices stay in `balance.json`. Rejected: a new config file, since the existing one already validates keys and has an owner's tool.
3. **Time:** the world's clock moves **once per round**, not per walk. World turns every N rounds, building times in rounds, weather and time of day by rounds. Rejected: counting every character's walks; time would stop when characters stay put and would run faster with a bigger cast, so runs couldn't be compared.
4. **First world:** The Thirteenth Stroke, moved from `state/worlds/` into `games/`. The backend stays world-independent (DEVELOPING.md invariant 7): no code, skill, check or dashboard names a world. **Forging new simulation worlds** (the worldsmith aiming at `--sim-complete`) is **phase 2**.
5. **Dice lines:** characters are **not** shown them by default; the story tells them what happened. A setting (`brief.dice_lines`) turns them on for comparison runs. This is a recorded exception to the proposal's section 2.
6. **Model per character:** the Agent tool takes a `model` at spawn (verified 2026-10-24: `npc` defined as Sonnet ran as Haiku when asked). One `player.md`; the referee passes the cast entry's model. Rejected: one agent file per model.
7. **Repository:** this folder, name CodeRPG-Sim, copied git history kept, new remote `github.com/LiminallyYours/CodeRPG-Sim`.
8. **The original's planning papers** are deleted from the fork (recoverable from git history and the original folder).
9. **Referee:** one turn procedure. `gm-turn` itself is edited to act for a named character and store the story with `narrate`; no second copy. The game-master `CLAUDE.md` and the in-game reminder hook are replaced **early** (step 3), so JW no longer needs `ooc:`.

Verified facts the plan relies on: `tools: []` + `omitClaudeMd: true` still give an agent no file tools and no `CLAUDE.md` (Claude Code's agent list wrongly labels such agents "All tools"); about 100 references to the single player's fields across 37 functions of `rpg.py`; the move counter (`tick_move`) drives the deadline clock, weather, time of day, building completion and world turns.

## Assumptions (confirmed by JW)

- **A. The two shipped games stay** in `games/` next to The Thirteenth Stroke, each with a small two-character `cast.json`, so the engine tests run the simulation on three worlds and prove nothing in the backend is tied to one. Only The Thirteenth Stroke gets the full simulation content and must pass `--sim-complete`. The alternative is deleting them, which leaves one world and no proof of world-independence until phase 2.
- **B. Phase 1 built rooms** record an `owner` and have one use, `stash`. The proposal's phase 2 says "room uses beyond stash", which puts stash in phase 1.
- **C. Contests** (two characters reaching for the same thing in the same turn) wait for phase 2 with trades. In phase 1 the round order decides who gets there first.

## The steps

### Stage 0: housekeeping
1. **The fork's own documents.** Commit `SIM-SESSION-HANDOFF.md`, `SIMULATION-FORK-PROPOSAL.md` (section 12 marked decided, section 10 extended with the decisions above) and this `PLAN.md`. Check: nothing else changes.
2. **Remove the original's planning papers.** `git rm` `HANDOFF.md`, `NEXT-PLAN.md`, `IMPLEMENTATION-PLAN.md`, `NEWSTAGEIDEAS.md`, `NEWSTAGEIDEAS-previous.md`, `UI-REDESIGN-SPEC.md`, `UI-REDESIGN-MOCK.png`, `ABOUT-v2.md`, `docs/`; delete the untracked `tempshots/` and `tempdocs/` (their originals in `../CodeRPG/` checked to exist first). Fix links to them in `README.md` and `DEVELOPING.md`, if any.
3. **Development mode.** Replace `CLAUDE.md` with a short note: this is the simulation fork, under construction; every message is development; read `HANDOFF.md`, `PLAN.md` and `DEVELOPING.md`. Remove the `UserPromptSubmit` hook from `.claude/settings.json` and delete `.claude/hooks/turn_reminder.py` (and its test, if `test_rules.py` has one). The meter's `SessionStart` hook stays. Start the fork's `HANDOFF.md`. Check: a fresh session gets no in-game reminder.
4. **The first world.** `python3 tools/worlds.py keep thirteenth_stroke`, moving it into `games/`. No content changes yet. Check: `validate`, and `test_rules.py`, which picks up every game in `games/`.

### Stage 1: many characters in one save
5. **The `simulation` preset.** Add it to `rules/presets.json`, with new keys added to all four presets (DEVELOPING.md: every preset has the same keys): `memory.recent_rounds` 5, `memory.condense_every` 5, `memory.max_chars`, `memory.condenser` self; `rounds.clock` (`move` or `round`: what moves the world's clock; `round` in simulation, so the existing `world_turns.every_moves`, set to 2 there, counts rounds); `brief.dice_lines` false; `clock.on` (false in simulation: no deadline); `curses.on` (false in simulation); `dashboard.port`. In simulation: generation of rooms and items off, side scenes off, `new_worlds` off. Keys nothing reads yet are only stored. Check: `tools/settings.py show` on a scratch copy; `validate` rejects a misspelt key.
6. **Players in the save, behaviour unchanged.** The save gets `players: {<id>: {location, stats, inventory, equipped, met, map, ...}}` in place of the single player's fields; `STATE_VERSION` 10, older saves refused (no migration, proposal section 9). Every function that read the player now takes a player id; `condition_flags` builds `has_`/`met_` per player; `npc_memory[<npc>][<player>]`; `run.present` per player; `view.players`. `--as <id>` is parsed in `main()`. **In this step only**, a save with one player and no `--as` acts as that player, so the 68 existing engine tests pass unchanged, which proves the refactor kept behaviour. `newgame` without a cast makes one player from `world.md` as now.
7. **The cast.** `games/<id>/cast.json` (proposal 4.1), read by `newgame`, which places each character at their `home` with their kit; `validate` checks it (unique ids, rooms and items exist, stats in range, models known: `sonnet`, `opus`, `haiku`, `fable`). Two-character casts for the two shipped games (assumption A); The Thirteenth Stroke gets a placeholder cast of two, replaced in step 15. `--as` becomes required on the player-acting commands of proposal section 9; the tests' `rpg()` helper adds it by default. New tests: two characters acting in one room (one takes an item, the other finds it gone); `--as` refused when missing or unknown.
8. **NPCs among several people.** `npc-brief` lists the characters present by name, as people, with no mark that they're players; an NPC's memory is per character. Test: the brief names both, and memory written for one isn't shown about the other. **Dry run** (two characters, one talk each).

### Stage 2: the record
9. **The log.** `state/log/<run id>.jsonl`, written through one function. This step logs `command` (each command run with `--as`, and its output) and `coins` (every change, with a reason). `coins` gains `--reason <job|work|sale|order|reward|...>`, required in simulation saves; `pay` and effects pass their own. `rpg.py log [n]` prints the last entries. Tests: every coin change in the log has a reason; the log is valid JSON lines.
10. **Rounds.** `round start` draws the order: a balanced shuffle from the run's seed and the round number, logged with the draw; `round end` checks every character acted, runs the world's clock tick (moved out of `move`'s `tick_move`: weather, time of day, building completion, world turn due every `world_turns.every_moves` ticks, which are rounds when `rounds.clock` is `round`) and logs the summary. A world turn that falls due runs at the round's end, so no character acts in the middle of one. Tests: the same seed draws the same orders; over 30 rounds no character goes before another more than a set margin more often; `move` no longer ticks the clock in a simulation save; a building finishes after its rounds.
11. **A player's turn, and memory** (built before the orders step, which needs each turn's own words; as built 2026-10-24). `reply <id> <file>` takes the player agent's reply (`DO:` and `JOURNAL:`) from a file in `proposals/` and opens their turn; `narrate <id> <file>` stores the story they're told and ends it. Files, not shell arguments, because the text carries quotes and apostrophes. In an open round only the player whose turn it is can be acted for; `round end` waits until every player's turn is narrated. Memory entries carry round, kind (`seen`, `told`, `did`, `reasoned`) and a times-shown count. `memory condense <id>` prints the condensing brief once the recent layer holds `recent_rounds + condense_every` rounds or passes `max_chars`; `memory store <id> <file>` folds those rounds into the player's own words; the log keeps the originals. Only the `self` condenser is built. Tests: turn order is enforced; condensing stores and trims; a store with nothing waiting, or after the memory changed, is refused.
### Stage 3: what a character knows
12. **Orders in the log.** `order` entries, all carrying the order id: `asked` (the character's words and journal line, passed by the referee), `shaped`, `priced`, `paid`, `delivered`; `used` each time the thing is used, moved or entered. Built rooms record an `owner`; `stash` (assumption B): items left in your own stash stay put. Test: one order from `asked` to `used`.

13. **`pane` and `brief`.** `pane <id>`: the status block as plain text from `view.players[<id>]` (health, money, belongings and weight, exits as `look` reports them, places visited, quests, rumours heard, people met). `brief <id>`: the opening (first turn only), condensed memory, recent memory, the status block; dice lines only if `brief.dice_lines` is on. Logged as a `brief` entry. Never: `## GM only`, flags, unannounced prices, other rooms, other characters' private state, the log, the meter. Test: no brief contains a word from the forbidden list (game, rules, dice, flag, agent, model, player, log, and the rules' own words: d20, DC, roll, check, `[agent]`, `[minor]`). **Dry run.**
14. **The player agent.** `.claude/agents/player.md`: `tools: []`, `omitClaudeMd: true`, no model (the referee passes it); a person in a place, replying `DO:` and `JOURNAL:`, naming no game. Check: one live spawn with a brief from a scratch copy; the reply has exactly the two parts.

17. **The Thirteenth Stroke for the simulation:** the approved additions and its cast of four (written with step 15's content, in one commit). Check: `validate --game thirteenth_stroke --sim-complete`.

### Stage 5: the referee
18. **The turn procedure for a named character.** Edit `gm-turn`: every rules command carries `--as <id>`; the story goes to `narrate` and the journal line to `journal`, never to a screen; the narration rules are unchanged. The `/newgame` skill is reworked for a cast (no opening narrated to a screen; the openings are delivered in the first briefs). `/game` and `/newworld` are left alone and unused.
19. **The referee's standing orders and `/rounds <n>`.** `CLAUDE.md` gives the referee's standing orders (proposal sections 2 and 6); the `/rounds` skill runs n rounds, following proposal 6.2 per character, plus condensing when `memory condense` says it's due, then stops. **Dry run:** two characters, three rounds, seeded, in a scratch copy; every `brief` read for leaks, every coin in the log traced to a reason. This step spends real tokens: about one referee turn and one player-agent reply per character per round.

   **Run control, approved by JW 2026-10-24:** `/rounds <n>` runs n rounds; `/rounds` alone runs until stopped. Either way a run also stops when nobody is still playing, or at `rounds.max_per_run` (a setting, 50 in every preset, 0 for no limit). The owner pauses or ends a run gracefully: by typing to the referee during a run (standing orders: finish the round in progress, then stop and answer), with `rpg.py run pause | resume | end` from any terminal, or with the dashboard's buttons (step 20). `round start` refuses while a pause or end is asked, so the round in progress always finishes; `/rounds` resumes a paused run (`run resume`); an ended run is closed for good, with a summary in the log. Esc stays the hard stop: the open round resumes from whoever's turn it was. **Built ahead of step 19** (its own commit): the setting, `run status | pause | resume | end`, and `round start`/`round end` honouring them; the `/rounds` skill and the standing orders are step 19's.

### Stage 6: watching
20. **Dashboard, live view.** `tools/dashboard.py`, standard library only, serves one page on `localhost:<dashboard.port>` from the log and the save: round and order; each character's location, health, money, belongings and latest journal line; a feed of actions with their journal lines and the narration each received; refreshes every few seconds. Two buttons, **Pause after this round** and **End the run**, which run `rpg.py run pause` / `run end` (the dashboard never writes game files itself). Test: the server's JSON endpoint on a fixture log; the page loads.
21. **CSV export.** One row per log entry, from the dashboard and as `tools/dashboard.py --csv <run>`. Test: row count equals entry count.
22. **Phase 1 close.** README and DEVELOPING rewritten for the fork, `HANDOFF.md` current, the seeded dry run repeated end to end.
